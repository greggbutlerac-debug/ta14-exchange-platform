# TA-14 Canonical 24-Link Dependency Map v1

**Status:** Canon-grounded research aid. This document does not add or rename doctrine. It extracts the dependency structure already defined in `apps/web/lib/academy/ta14-24-link-canon.ts` so technical-differentiation and prior-art analysis can compare mechanisms rather than labels.

## Parent architecture and provenance

The canonical source preserves the May 1, 2025 Chain of Eight:

`Reality -> Record -> Continuity -> Admissibility -> Binding -> Commit -> Execution -> Outcome`

The 24-link architecture is the higher-resolution decomposition and maturation of that existing parent route.

## Five canonical architecture regions

1. **Reality & Evidence** — Links 01-06
2. **Reliance, Authority & Consequence Formation** — Links 07-11
3. **Binding & Commit** — Links 12-15
4. **Execution & Admissible Non-Occurrence** — Links 16-19
5. **Outcome, New Reality, Memory & Future Chain** — Links 20-24

## Canonical branching after Commit

The canon defines two legitimate post-Commit paths rather than treating execution as the only successful ending.

### Execution-capable route

`15 Commit -> 16 Execution Reality -> 19 Execution -> 20 Outcome Reality -> 21 Outcome -> 22 New Reality -> 23 Memory -> 24 Future Chain`

### Non-occurrence route

`15 Commit -> 16 Execution Reality -> 17 Admissible Non-Occurrence -> 18 Prevented Consequence -> 20 Outcome Reality -> 21 Outcome -> 22 New Reality -> 23 Memory -> 24 Future Chain`

Canonical teaching rule: **reaching Execution is not the highest score; preserving admissibility is the goal. Non-execution can be a governed success when continuation is no longer admissible.**

## Why the dependency structure matters for differentiation

The architecture is not a flat 24-item checklist. Several canonical behaviors arise from dependencies:

1. **Evidence is progressively transformed, not merely collected.** Record and continuity feed Evidence Governance; governed evidence is tested for admissibility; admitted evidence bounds Admissible Truth; bounded truth then supports Reliance.
2. **Authority is necessary but not sufficient.** Reliance precedes Authority, and Legitimacy separately tests whether otherwise valid authority is proper in context.
3. **Consequence is governed before it forms.** Consequence Formation and Attachment / Assent occur before Binding Reality and Binding.
4. **Reality is re-contacted repeatedly.** Reality is not only the starting point. Binding Reality, Commit Reality, Execution Reality and Outcome Reality force new contact with current state at separate consequence boundaries.
5. **Binding and Commit are distinct.** Binding makes the determination operative within explicit scope; Commit separately authorizes the exact transition into action after another reality check.
6. **Refusal/non-execution has first-class governance standing.** Admissible Non-Occurrence and Prevented Consequence create an evidence-bearing alternative to execution rather than treating refusal as system failure.
7. **Execution does not close the chain.** Outcome Reality must be observed, Outcome governed, New Reality recognized, Memory controlled, and Future Chain explicitly launched.
8. **The architecture is recursive.** A governed result changes reality; that new reality and controlled memory become constrained inputs to a later chain.

## Prior-art comparison rule derived from the canon

A comparator should not receive full equivalence credit merely because it has a component with a similar name or function. Full-link equivalence requires evidence that the comparator provides the **same material transition role** and the **same dependency consequence**.

Example: a system that checks current state before a command may be a partial analogue to Binding Reality, Commit Reality or Execution Reality, but it is not automatically equivalent to all three. The comparison must show whether those checks occur at materially distinct governance boundaries and whether failure returns, holds, refuses or redirects the consequence path in an equivalent way.

## Highest-value destructive tests implied by canonical dependencies

1. **Admissible Evidence -> Admissible Truth test:** Can a comparator distinguish evidence validity from the bounded truth proposition it is permitted to support?
2. **Authority -> Legitimacy test:** Can an actor possess valid authority yet be barred because use of that authority is illegitimate for the purpose/scope/context?
3. **Consequence Formation -> Attachment / Assent test:** Is emerging consequence modeled and governed before obligation/consequence attaches?
4. **Binding Reality -> Binding -> Commit Reality -> Commit test:** Are these four transitions materially separate, with fresh-state checks on both sides of Binding?
5. **Execution Reality -> Non-Occurrence/Prevention test:** Can non-execution obtain affirmative governed standing and can the prevented consequence itself be evidenced rather than inferred from a denial?
6. **Outcome Reality -> Outcome test:** Is real post-action state observed before outcome classification, rather than treating successful command execution as outcome proof?
7. **Outcome -> New Reality -> Memory -> Future Chain test:** Does the result become governed state and controlled memory that explicitly constrains the next chain?

## Research boundary

This map describes TA-14's canonical architecture and identifies what a technical comparator would need to match. It does not by itself establish novelty, non-obviousness, patentability, infringement, validity or freedom to operate.
